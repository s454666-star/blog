# Telegram content features

Enable `file_fingerprints_enabled` and explicitly list source aliases in
`fingerprint_source_aliases`. No other sources are changed. Features are
Base64-encoded SHA-256 of full file bytes, never names or Telegram message text.

`processed_messages.fingerprint_base64` stores original document/photo/ZIP
features. `processed_archive_items.fingerprint_base64` stores extracted media
features. `file_features` deduplicates across peers, aliases and ZIP children.
`telegram_file_features` caches immutable Telegram object identities (including
document size or the largest photo representation). A different Telegram object
ID cannot prove identical bytes without downloading it at least once.

Only fingerprints associated with successfully delivered or historically
completed media may suppress new delivery. Hashing alone does not mark content
delivered. Verified downloads are reused after crashes. Identical bytes under a
new object ID are downloaded to owned staging, hashed and discarded after the
ledger commit. Normal nonduplicate videos are moved to the configured download
directory for the existing review scanner. Features do not remove old files.

The same worker alternates normal source batches and feature backfill batches.
Backfill visits completed message rows only, reuses exact anonymous local output
when available, otherwise downloads into `fingerprint_work_dir`. Historical
output is never forwarded or moved again. Original ZIPs and available extracted
children are hashed; original source messages are retained. Failed staging stays
for retries and sanitized errors are recorded. FloodWait leaves the cursor in
place and reaches the existing rate-limit wait handler.

`fingerprint_progress` is independent of normal download cursors. Reports count
current configured peers only. `covered_through_id` is the greatest completed
media row before the first missing/failed feature, not the largest seen ID and
not a claim that every integer ID contains media. `highest_written_id` includes
out-of-order successes. Failed backfills remain visible and retry after an hour.
`python telegram_media_queue.py --fingerprint-status` prints anonymous counts,
coverage and failures. `fingerprint_jobs` records per-message feature outcomes;
these never overwrite the existing processing/completed/failed delivery status.

Deploy both Python modules together after backing up runtime/config/state/DB.
Use a safe idle boundary for the initial upgrade. Future workers accept
`stop-after-cycle.flag` and hold a Windows process lock. Remove that flag before
starting the scheduled task. Do not use the old reload script that deletes
partial download directories for a feature deployment.

Tests use generated bytes and synthetic ZIPs (including encrypted ZIPs), isolated
SQLite files, mocked network calls and the local 7-Zip executable. No live media
is inspected or rendered.
